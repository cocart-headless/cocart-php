# Next Changelog for CoCart PHP SDK <!-- omit in toc -->

> [!WARNING]
> This changelog is **NOT** final. It lists the changes waiting for the next release of `cocart-headless/cocart-php`, to be moved into a changelog under the new version when it's released.

## Changed

- **Retries never send a change twice.** With `max_retries` set, a request that changes something (a POST, PUT or DELETE: placing an order, paying, adding to the cart) is no longer sent again after a timeout or a dropped connection, as it may already have run on the store: a retried checkout could charge the card twice. A 429 is still retried for any request, since the rate limit refuses it before it runs, and a 503 or timeout for a GET.
- **`Response::getNotices()` returns notices keyed by type** (`['success' => [...], 'error' => [...]]`), which is how CoCart sends them. The docblock described a list. When there are none it returns `[]` (CoCart Starter 5 sends `{}`, CoCart 4.x `[]`).
- **A guest cart that no longer exists is replaced automatically.** CoCart Starter 5 refuses a cart key with no cart session on every cart route (`cocart_invalid_cart`), for example after the cart expired. The client then forgets the cart key (also in `$_SESSION`) and retries the request once as a new guest, so the shopper isn't stuck. With a `SessionManager` storage adapter, save the new key with `$session->setCartKey($client->getCartKey())`.
- `CoCartInterface::requestRaw()` takes a fifth argument, `array $options = []` (`omit_cart_key`). Classes that implement the interface themselves need to add it.
- **`main_plugin` `'basic'` is renamed `'starter'`**, after the CoCart Starter plugin. It's the default and what `getMainPlugin()` returns. `requiresBasic()` is renamed `requiresStarter()`.
- **A 409, a 429 or a 5xx is always a `CoCartException`, never a `ValidationException`**, whatever its code says. A `409 cocart_order_invalid_status` (an order already paid) was a `ValidationException` because its code contains `invalid`. 400 is still a `ValidationException` and 401/403 an `AuthenticationException`.
- **A retry after a 429 waits as long as `RateLimit-Retry-After` says**, which is what CoCart Plus sends, then `Retry-After` (what a proxy may send), up to 60 seconds. Only `Retry-After` was read.
- **The ETag cache no longer keeps a response whose `Cache-Control` says `no-store` or `private`.** CoCart Plus marks its checkout, order and account responses that way, since they hold a customer's details.

## Added

- `Response::getShipping()` returns the cart's whole `shipping` field: the package count, whether shipping has been calculated, and the packages.
- `Response::getExtensions()` reads the cart's `extensions`, and `Response::getRateLimit()` the `RateLimit-*` headers (`limit`, `remaining`, `reset`, `retry_after`).
- Methods for the CoCart Plus 2.0 routes the SDK didn't cover: `cart()->getMini()`, `cart()->removeCoupons()`, `cart()->removeAllItems()` (keeps coupons and fees), `products()->shippingRates()`, `products()->createReview()`, and on `account()`: `register()`, `updateAddress()`, `cancelOrder()`, `verifyEmail()`, `sendOrderEmailVerification()`, `verifyOrderEmail()`, the subscription methods (`getSubscriptions()`, `getSubscription()`, `suspendSubscription()`, `reactivateSubscription()`, `cancelSubscription()`, `setSubscriptionAutoRenew()`, `updateSubscriptionPaymentMethod()`, `resubscribe()`, `cancelResubscribe()`) and `requestOrderWithdrawal()`.
- `applyCoupon()` and `checkCoupons()` take an optional email for coupons restricted to certain emails; `addFee()` takes an optional tax class.
- `CoCartException::getCart()` returns the cart sent with an error: `cocart_item_not_in_cart` carries the current cart since CoCart Starter 5.
- `CoCartException::getFields()` returns every field at fault, by path, with its message (`['billing.postcode' => '…']`, `[]` when there are none), since CoCart Plus checks a whole form at once. `getField()` returns the first one and `getReason()` the underlying plugin's own reason, or `null`.
- **Choices for CoCart Plus's supported plugins.** `addItem()`'s options are documented for a subscription plan (`convert_to_sub`), a gift recipient (`recipient_email`) and a warranty (`item_data['warranty']`); other plugins' fields still pass through. `cart()->changePlan($itemKey, $value)` switches a cart item to another plan, or to one-time with `'0'`.
- `docs/extension-data.md` lists the data CoCart Plus adds under `extensions` for the plugins it supports, and how to send the customer's choices.
- **Checkout (CoCart Plus 2.0).** `$client->checkout()` places orders and takes payment: `placeOrder()` with `payment_data` as a map of the keys the gateway reads (`['wc-stripe-payment-method' => 'pm_…']`: gateway tokens only), and a free order needs neither `payment_data` nor `payment_method`. It returns a `CheckoutResult` read from the order's `result`: `getCode()` (`order_placed`, `action_required`, `payment_pending`, `payment_failed`, or `payment_method_changed` for a subscription), `isComplete()`, `isAwaitingPayment()` (the order is placed and the customer still pays: Cash App Pay, WeChat Pay, Stripe vouchers, BLIK, a Multibanco voucher…), `needsConfirmation()` for 3D Secure, `needsRedirect()` for an off-site step, `isPending()` when the gateway hasn't confirmed yet, `isFailed()`, `getObject()`, the order's `getOrderId()`, `getOrderKey()`, `getOrderNumber()` and `getOrderStatus()`, `getSubscriptionId()`, `getRedirectUrl()` (https or http only), `getClientSecret()`, `getIntentType()`, `getPaymentMethodType()`, `getMessage()`, `getErrorCode()`, `getGatewayErrorCode()`, `getGatewayMessage()`, `getActionType()`, `getActionData()` and `getResponse()`. A declined card is a result to read, not an exception. `var_dump()` and `print_r()` of a result mask the client secret, the order key and URL query values. `payForOrder()` (including 3D Secure) and `confirmReturn()` return the same result; both send the order key in the body. Also `get()` (with `currency`, `formatted` and `thumb`; call it for the review page, as CoCart Plus checks the total against it), `update()` (`result.not_applied` lists what wasn't applied), `process()`, `getConfig()`, `getPaymentMethods()`, `getSavedPaymentMethods()` (each with `id`, `gateway_id`, `label`, `type`, `expires`, `is_default` and `supports_subscriptions`), `searchAddresses()`, `getAddressDetails()`, `getOrderReceived()` (with `formatted` and `meta_keys`) and `confirmOrderPayment()`. See `docs/checkout.md`.
- **Checkout: finding out how an order ended when no answer came back.** `placeOrder()` sends each order with a random `checkout_id`, or yours in the input (16 to 64 letters, digits, `-` or `_`; anything else is a `ValidationException`, `checkout_invalid_checkout_id`, before sending). When the connection drops, the request times out, a proxy gives up waiting, or another request is still taking payment for the cart (`409 cocart_payment_in_progress`), it throws `CheckoutOutcomeUnknownException` (a `CoCartException`) with `getCheckoutId()`, and `checkout()->getStatus($checkoutId)` returns its `code` (`order_placed`, `payment_required`, `in_progress` or `not_placed`), `message`, and the order's `order_id`, `order_key`, `order_number` and `order_status`.
- `account()->updateSubscriptionPaymentMethod()` takes a new card in `payment_data` as well as a saved card's `token_id`, and returns a `CheckoutResult` read from the subscription (`getObject()` is `subscription`, with `getSubscriptionId()`), since a new card may need 3D Secure.
- `account()->getOrders()` filters by `status` (one or a list), `after` and `before` (ISO 8601) and `subscription_order_type`, and `getSubscriptions()` by `status`. `getProfile()`, `getOrders()`, `getOrder()`, `getGuestOrder()`, `getSubscriptions()` and `getSubscription()` take `formatted` and `meta_keys`. A list is sent comma-joined, and `true`/`false` as `'true'`/`'false'`.

## Fixed

- **`Response::getShippingMethods()` returned the whole `shipping` field instead of the packages.** CoCart sends shipping packages keyed by package ID under `shipping.packages`; `getShippingMethods()` now returns them as a list.
- **`applyCoupon()` was rejected by CoCart Plus** because it sent the code as `coupon` instead of `code`. The batch example in `docs/cart.md` made the same mistake.
- **`addFee()` was rejected by CoCart Plus** because it sent the amount as a number; the route takes a string.
- **`Response::getFees()` returned the fees keyed by fee ID instead of a list.** It now returns them as a list.
- **`account()->changePassword()` and `getReviews()` called routes CoCart Plus doesn't have.** The password now goes to `POST /my-account` (only `password_current`, `password_1` and `password_2`), and reviews come from `products/reviews/mine`.
- **`removeCoupon()` broke for coupon codes with spaces, `%`, `#` or `?`.** The code went into the URL unencoded. It's now encoded.
- **The docs sorted products by `price`, which CoCart rejects.** `sortBy()` and the docs now list the sort orders CoCart accepts: sort by price with `price_asc` or `price_desc`.
- **Connection error messages could include the cart key.** The Guzzle and stream adapters put the full request URL, query string included, in the exception message. The query string is now removed from any URL in a transport error message.
- **The Guzzle adapter threw a `TypeError` instead of a `CoCartException` on a connection error.**
- The docs read product prices from `price` and the product list as a plain array. Prices are under `prices` (minor-unit strings) and the list is under `products`.
